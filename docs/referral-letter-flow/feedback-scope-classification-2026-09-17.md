# 紹介状フィードバック：追加改修と既存不備の切り分け

整理日：2026年9月18日。実装は変更していません。

## 結論

今回の依頼は、主に**新しい元データへの更新と、表示・案内方法の仕様変更**です。一方、電話案内への主な困りごとの差し込みは当初仕様にもあり、既存仕様への修正候補として切り分けるのが妥当です。

「検収時に出た依頼」をすべて「既存不備」とは扱いません。また、追加改修という分類が、そのまま追加費用の発生を意味するものでもありません。費用・対応責任は、契約範囲と先方との合意記録を別途確認して決めます。

## 1. 分類基準

| 区分 | 判断基準 |
| --- | --- |
| 追加改修・仕様変更 | これまでの対象データ、表示内容、動作、対象外事項を新たに変える依頼 |
| 既存不備の修正 | 既に求められていた動作が実現していない、または壊れているもの |
| 要確認 | 仕様と後続の変更経緯が食い違う、元データが未確定、または動作確認が終わっていないもの |
| 既存対応済み | 現在の実装で既に実現しており、今回の追加作業は不要なもの |

基準にしたのは、元仕様書、会話内の後続指示、9月6日の検収チェックリスト・点検結果です。チェックリストは当方作成の確認資料であり、それだけで先方の承認済み仕様と断定していません。旧仕様書と後続指示が異なる場合は、後続指示も踏まえています。

### 電話案内を不備候補とする根拠

元仕様書の「説明書」には、主な困りごとを①として、電話案内へ差し込む指定があります。一方、現在は「困りごとについて相談できる窓口を知りたい」という共通文です。

過去の依頼は「どの選択肢が来ても自然な日本語にする」であり、必ずしもカテゴリ名を消す指定ではありません。したがって、今回の「お金について相談できる窓口を知りたい」への修正は、**元の差し込み要件と自然な日本語の両方を満たす修正**と整理できます。

ただし、共通文への変更自体を先方が承認していた場合は、承認後の再変更という整理もあり得ます。履歴だけで費用負担までは断定しません。

## 3. 既存の検収で見つかった問題・未完了事項

今回のWordにある新しい希望と、9月6日の点検で残っていた事項は別に管理します。

| 項目 | 分類 | 記録上の状態 | 今後の扱い |
| --- | --- | --- | --- |
| ビルドの型エラー | 既存不備 | 修正済み。点検記録では未使用importを削除し、ビルド成功 | 今回の追加改修へ含めない。新たな未修正不備としても数えない |
| 「お金ので…」という不自然な日本語 | 過去の表示不備 | 共通の自然な文への修正済み。ただし主な困りごとの差し込みは上記のとおり別途整理が必要 | 日本語の不備と、差し込み要件の欠落を分けて扱う |
| 相談候補なし画面に通常操作で到達できない（検収3-10） | 要確認：仕様・データと検収手順の不整合 | 画面・分岐は実装済みだが、旧データでは「お金」の全回答に紹介先があり候補が必ず残る | 分岐の実装漏れとは断定しない。修正版導入後の候補条件を確定し、実データで再検収する |
| 印刷プレビュー・PDFの最終ページ割り（検収6-4） | 既存検収の未完了 | 印刷呼び出し・CSSは確認済み。最終の目視確認は未完了 | 未確認＝不具合ではない。既存レイアウトで欠けがあれば不備修正、新しい文面や切り取り線に伴う調整は追加改修側に分ける |
| 紹介状本体の緊急度バッジを非表示にする | 既存対応済み | 前回の実装確認では非表示 | 今回のバッジ位置変更と混同しない。再改修は不要 |

上記の「修正済み」は既存の点検記録・前回確認に基づきます。今回、アプリ起動やビルドの再実行はしていません。

## 4. まだ不備と断定しない項目

| 項目 | 現時点の分類 | 判断に必要なこと |
| --- | --- | --- |
| 紹介先を削除した回答にも市町村への問い合わせ案内が出る | 原則は仕様変更の詳細確認 | 既存検収5-5では空欄時の共通案内を想定していた。今回の「削除」が、共通案内まで消す意味かを確認する。共通案内の存在だけで既存不備とはしない |
| 紹介先削除に伴い、困りごとの候補からも外すか | 候補判定の仕様確認 | 「紹介先があれば表示する」という既存指示はあるが、「紹介先がなければ必ず候補外」とは限らない |
| 若者のキャリアプラン末尾の点数が空欄 | 元データの確認事項 | シートのC46が空欄。実装側の点数転記漏れとは断定できない |
| Wordとシートで紹介先の順番・名称が異なる | 原稿の整合確認 | 正本を決める。どちらか一方と異なるだけで実装ミスとしない |
| 「低・中・高」と「小・中・大」の混在 | 表記確認 | 従来の明示指示は「低・中・高」。新しい呼称を採用するなら仕様変更 |
| PNG・紙でのURL表記、切り取り線の表示対象 | 追加改修の詳細仕様 | リンク機能の追加に合わせて決める。既存PNGでリンクがクリックできないことは不備ではない |

## 5. 作業のまとめ方

| 管理枠 | 含めるもの |
| --- | --- |
| 既存仕様の是正 | 電話案内へのカテゴリ差し込み。ただし共通文の承認経緯を確認する |
| 既存検収の完了 | 印刷の最終確認、候補なし条件と検収手順の整合整理。確認結果に応じて不備を起票する |
| 追加改修①：元データ更新 | 修正版9.10への差し替え、回答追加・文言修正・紹介先更新・削除 |
| 追加改修②：紹介先の拡張 | 紹介先①②、各URL、2件分の検索案内、保存・印刷時の表記 |
| 追加改修③：文書の見せ方 | 見出し、紹介状からの相談先削除、バッジ位置、訪問案内、注意書き、切り取り線 |

追加改修に伴うテストと検収表更新は、それぞれの改修に必要な確認作業として含めます。検収表を新仕様に書き換えることで、旧仕様に対する不備の有無を曖昧にしないよう、旧版も残します。

## 6. 先方へ伝える場合の要約

> 今回のご要望は、修正版データへの更新、紹介先の複数表示・リンク追加、説明書と紹介状の掲載内容の見直しが中心となるため、主に追加改修・仕様変更として整理しています。一方、電話案内に主な困りごとを差し込む点は、当初仕様との整合を確認し、既存仕様への修正として扱う方向です。既存検収で残っている印刷確認等は、新しいご要望とは分けて完了させます。紹介先を削除した場合の案内、切り取り線の対象などは、意図を確認したうえで対応範囲を確定します。
