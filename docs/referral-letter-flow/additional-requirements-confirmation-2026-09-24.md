# 紹介状機能：追加改修前に先方へ確認する事項

整理日：2026年9月24日

9月17日の修正依頼の整理、9月18日の対応方針メール、9月21日23:07の鎌谷様の返信、その後の対応内容を基に整理した。9月21日の返信では、既存修正と追加要件の仕分け、進め方、9月末を目処とするスケジュールについて了承を得ている。ただし、以下の個別仕様まで確定したという意味ではない。

シートのセル位置や不整合は9月18日の確認記録に基づく。9月24日時点のシートを再取得したものではないため、確認依頼を送る前に先方の修正が既に入っていないか確認する。

## 1. 実装前に回答をいただきたい事項

| 優先 | 確認すること | 先方への質問文 | 決定によって変わること・こちらの提案 |
| --- | --- | --- | --- |
| 最優先 | 紹介先を削除・空欄にした回答を、困りごとの候補に残すか | 紹介先①・②がどちらも空欄の回答について、困りごと自体は選択できるように残しますか。それとも、選択候補から除きますか。回答によって意図が違う場合は、対象の回答ごとにご指定ください。 | 紹介先の削除と候補からの除外は別の処理。例として「お金／該当しない」と「高齢・家の片付け／ゴミ捨てができていない」は同じ扱いでよいとは限らない。一律に候補外にはせず、先方の意図を確認する。候補が1件もなくなる場合は紹介状を生成しない既存の分岐が使われる。 |
| 最優先 | 候補に残すが紹介先がない場合の案内 | 上記で候補に残す回答に紹介先がない場合、現在の「お住まいの市町村の相談窓口」という代替案内を残してよいですか。それとも相談先の行を非表示にしますか。主な困りごとに選んだ場合の電話・検索案内も併せてご指定ください。 | 空欄にするだけでは、現在の代替案内は消えない。提案は、代替の市町村案内を残すかどうかをまず決め、非表示にする場合は存在しない相談先を使った検索案内も出さないこと。 |
| 高 | 若者のキャリアプラン末尾の緊急度 | 若者分野の「将来的な働き方（キャリア形成）を考える必要がない」は、子育て分野と同様に緊急度の点数を0としてよいですか。 | 9/18確認時、若者の修正版シートC46が空欄。0と点数なしは別扱いなので推測で補完しない。点数と、困りごと候補に含めるかは分けて決める。 |
| 高 | Wordとシートで異なる紹介先の名称・順序 | 紹介先の名称と①②の順序は「修正版9.10」のシートを正としてよいですか。例えば高齢・移動の紹介先は、シートの順に①地域包括支援センター、②社会福祉協議会でよいでしょうか。 | Wordでは逆順で、社会福祉協議会の括弧書きにも違いがある。質問・回答・紹介先・URLはシート、画面の文面・構成はWordを正とする提案。例示された別テーマの相談先を固定表示することはしない。 |
| 高 | URLのある紹介先にも検索方法を併記するか | 直接開けるリンクがある紹介先にも、ネット検索の案内を併記してよいですか。全国の検索サイト等についても「紹介先名＋お住まいの市町村名＋電話番号」という案内でよいでしょうか。 | 原稿どおりならリンクと検索案内を併記し、主な困りごとの紹介先が2件なら2件分を表示する。全国サイトなどに別の案内が必要であれば、対象と文言を指定いただく。その他の困りごとの検索案内は追加しない。 |
| 高 | 保存画像・印刷物にURL文字列を載せるか | 画面では紹介先名を押すとリンク先を開く形にします。画像や紙では押せないため、紹介先名と検索案内だけでよいですか。それともURL文字列も掲載しますか。 | 提案は画面にリンク、画像・紙には紹介先名と検索案内を表示すること。URL掲載を希望する場合は長いURLによる折り返し・改ページも調整する。QRコードは追加しない。 |
| 高 | 切り取り線をどこに表示するか | 切り取り線は印刷物だけに必要ですか。通常画面・保存画像にも表示しますか。また、説明書と紹介状が別ページになる場合は省略してよいですか。 | 提案は印刷用だけに表示し、別ページになる場合は省略すること。ただし、ページ境界に応じた制御方法は実装時に検証する。A4一枚への強制縮小は行わず、長文は自然に複数ページにする。 |

最初の2項目は、同じ回答について「候補に残すか」と「どの案内を出すか」を別々に答えていただく。紹介先が空欄の回答がすべて「困っていない」とは限らないため、空欄だけを根拠に判定しない。

## 2. 提案を添えてまとめて了承をいただけばよい事項

| 項目 | こちらから提示する案 |
| --- | --- |
| 紹介先が1件の場合の見出し | 1件なら「相談先」、2件なら「相談先①」「相談先②」。①とURL①、②とURL②を必ず組として扱い、URLがなければ名称のみ表示する。 |
| URLの不要な計測パラメータ | 接続先が同じであることを確認できたものに限り、`utm_source=chatgpt.com` などの計測用パラメータを除く。検索条件や対象施設を指定するパラメータは削除しない。 |
| 更新対象の版 | 「修正版9.10」の3タブを確定版として取り込む。実行時にシートへ自動接続する仕組みではないため、以後の変更は変更箇所を連絡いただいて反映する。9.10以降の修正がある場合は、実装開始前に知らせていただく。 |

## 3. 原則として再質問しなくてよい内容

以下は依頼書に明記されているか、その後のやり取りで方向性が共有されている。新たな異論がなければ、その内容で進める。

| 内容 | 扱い |
| --- | --- |
| 修正版9.10の質問・回答・紹介先への更新 | 追加改修として扱う。空欄・不整合は上記の回答を待って確定する。 |
| 主な困りごと・その他の困りごとの紹介先①②と各URL | 説明書に掲載し、URLがない名称にはリンクを付けない。 |
| 見出しへの用途の追記 | 「説明書（あなたに読んでいただく用）」「紹介状（相談窓口にお渡しする用）」にする。 |
| 紹介状本体から相談先を削除 | 主・その他とも相談先を説明書へ集約する。困りごとのカテゴリ・回答文は残す。 |
| 訪問時の案内と注意書き | Wordの指定文面を使用する。注意書きの新たな作文や独自の意味変更はしない。 |
| 緊急度 | 9/18の報告どおり「低・中・高」を維持。配置変更は対応済み。紹介状本体には表示しない。 |
| 電話案内2か所 | 主な困りごとのテーマを差し込む修正は対応済み。9/21の追加指摘も対応し、9/22にユーザーから公開反映済みとの報告あり。追加改修の未対応事項として再計上しない。 |
| 従来の基本条件 | 3分野・各7問、主1件＋その他最大3件、任意入力、サーバーへ送信しないこと、QR・共有URLを追加しないことは維持する。 |

## 4. 先方への仕様確認とは分けて、こちらで行う作業

- 確定したシート全行について、回答と紹介先①・URL①・紹介先②・URL②の対応を照合する。
- リンクの接続可否と、名称に対応するページかを確認する。不明な宛先だけ先方に照会する。
- 紹介先0件・1件・2件、候補なし、主1件＋その他3件の分岐を検証する。
- 更新前にタブ内へ保存した回答の復元が不整合を起こさないよう対応する。
- 保存PNG・印刷プレビューの文字欠け、長文時の改ページ、切り取り線の表示を確認する。
- 合意後の仕様に点検表を合わせる。以前の「○」を新仕様の検収完了として扱わない。

印刷の目視確認が未完了であること自体は、先方に仕様を決めてもらう事項ではない。レイアウトの要望を確定したうえで、こちらで検証する。
